How it works

Hashing, timestamps and independent verification

The core technology behind IP Custody, explained in plain language first and then in detail. You can also fingerprint a file right here in your browser.

The simple version

Say you've made something: a sketch, a song, AI art, code or a business idea. You want to be able to show that you had this exact thing on this exact date.

Emailing it to yourself, saving a dated file or visiting a notary are easy to dispute or lose. Blockchain timestamping is harder to dispute.

Your file gets a unique digital fingerprint: a SHA-256 hash, a short string of letters and numbers. That fingerprint, not your file, is sent to a public blockchain, which records when it arrived. Later, anyone can recompute the fingerprint from your file and check it against the public record. IP Custody can't quietly change or delete that record.

The process in three parts

  1. Hashing. Your file (document, image, code, etc.) is turned into a unique cryptographic fingerprint. Even one tiny change creates a completely different hash.
  2. Blockchain recording. The hash is recorded on a public blockchain with a timestamp. Public blockchain records are designed so they can't be changed after the fact.
  3. Verification. Anyone can compare your file's current hash with the blockchain record. If they match, the file existed unchanged at that time.

Why it matters: the record is tamper-evident, anyone can check it independently, and your original file stays private.

Step by step: what happens to your file

  1. Hashing

    Your file, whatever its size, goes through a one-way function and comes out as a fixed-length 64-character hash.

  2. Anchoring

    Your hash is batched with many others into a Merkle tree, and only the tree's root goes into a blockchain transaction.

  3. Timestamping

    Once the block is confirmed, its time becomes part of the permanent public ledger.

  4. Proof

    You keep a compact proof: your hash, the Merkle path (sibling hashes) and the block reference.

  5. Verification

    Anyone can recompute the hash, climb the Merkle path and compare it with the on-chain root. No need to trust IP Custody.

Privacy by design. Your original file is never put on-chain. Confidential IP stays off-chain in your vault or on your own device, and only a cryptographic commitment (a hash or Merkle root) is anchored.

Merkle trees, briefly

A Merkle tree is how many fingerprints fit into a single blockchain entry. Each file's hash is a leaf. Pairs of hashes are hashed together, level by level, until one Merkle root remains. Only that root is anchored.

To prove your file was included, you only need your leaf plus a few sibling hashes (the Merkle proof). Change one character in your file and the leaf changes, so the whole path changes and the root no longer matches.

Proofs stay small: a tree with a million leaves needs only about 20 sibling hashes (log₂ 1,000,000 ≈ 20).

              MERKLE ROOT  ──►  blockchain anchor
               /        \
          H(1,2)        H(3,4)
          /    \        /    \
        H1      H2    H3      H4
        │       │     │       │
      file1   file2  YOUR    file4
                     FILE
Proof for your file = H3 + H4 + H(1,2)

Anchoring: OpenTimestamps, Bitcoin and other networks

OpenTimestamps (OTS) is an open, vendor-neutral protocol for provable blockchain timestamps, created in 2016 by Bitcoin Core developer Peter Todd. You hash your file locally, public calendar servers aggregate many hashes into a Merkle tree, and the root is committed to Bitcoin (for example in an OP_RETURN output). You keep a small .ots proof file. It can be checked against any Bitcoin node or block explorer, even if the calendar server or IP Custody no longer exists.

The current IP Custody prototype prepares anchors along exactly this route: Bitcoin OP_RETURN / OpenTimestamps. A certificate stays marked UNBOUND until a transaction has actually been confirmed. We never make up a transaction ID.

Planned hybrid architecture

  • Fast layer: quick anchoring on a high-speed network such as Polygon, so the certificate arrives quickly.
  • Security layer: periodic aggregate Merkle roots committed to Bitcoin via OpenTimestamps for long-term verifiability.
  • Multi-chain checkpoints (higher tiers): one evidence-set Merkle root anchored on Ethereum, Polygon, Solana and/or Bitcoin. For each checkpoint the system records the chain, transaction ID, block reference, timestamp, root hash, evidence manifest and verification state.

The cryptographic evidence chain

  • Artifact
  • Hash
  • Event
  • Evidence manifest
  • Merkle tree
  • Merkle root
  • Blockchain anchor

Every significant action (upload, new version, search, snapshot, certificate) can be written as a standard evidence event with an ID, actor, action, project, artifact, timestamp, source, agent and version, input/output references, hash, evidence ID and system version. You get one consistent provenance record across every tier.

Evidence, not legal conclusions. IP Custody records that a file or action was captured at a certain time. That is separate from legal conclusions such as ownership, inventorship, novelty, patentability, infringement or enforceability. Those are for you, your attorney and the courts.
